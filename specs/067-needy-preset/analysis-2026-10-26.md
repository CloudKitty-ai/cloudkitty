## HIGH (design holes; fix before any code)

- **H1 proposer relief map.** The plan judges the proposer by the
  activity's governing need. The actor also gains Cuddle from grooming a
  friend (`groom_cuddle_pay`) and from co-sleep (both cats). A masked
  Cuddle leaks through the kitty's own groom-response and an own
  co-sleep running at onset; a masked Bath wrongly blocks grooming a
  friend. Fix: `proposer_relief(action) -> NeedSet` (Eat→Eat, Drink→
  Drink, Sleep{None}→Sleep, Sleep{Some}→Sleep+Cuddle, Rest{Some}→Cuddle,
  Rest{None}→none, Groom{None}→Bath, Groom{Some}→Cuddle, Play/Chase→
  Play) used by the verdict, the onset ending and the post-filter;
  T005's cross-check extended to the actor's moved needs; a T006 case
  for an own co-sleep at onset.
- **H2 partner rule placement.** `available_friend_in` is read by
  validate, `refusal_reason`, the RL legal mask replay, the prune (and
  its snapshot twin that `finish_what_you_started` reads), contagion
  and `is_conscriptable_friend`. A mask rule there leaks the target's
  hidden state to a covered seat's legal mask and yields spurious,
  mislabelled refusals. The groom effects arm has no availability
  filter at all. Fix: leave it alone; an engine-only predicate at the
  Rest/Sleep effects filters (`action.rs:871/:900`) and a new check in
  the groom arm (`:812–836`).
- **H3 state keyed on the config string.** The binding defaults
  unnamed kitties to External (`episode.rs:154–160`); persist re-stamps
  behaviour from config on resume; `control={"kitty_1":"needy"}` and
  `kitty-eval --brain needy` seat the preset with no state and no
  acknowledgement. A policy seat can be masked. Fix: advance and verdict
  require the DRIVING behaviour to be a needy name; `Episode` refuses
  control overrides that disagree with a needy config seat; persist
  reconciles `needy` with the re-stamped behaviour; one test per route.
- **H4 the state rides the wire.** `Kitty.needy` is cloned into every
  friend's fog view (`fog_for` blanks only memory and waypoint) and so
  into the plugin decision request, bc-collect's trace and `GET /state`,
  against FR-012/FR-014. Fix: blank `needy` on friends in `fog_for`;
  the spec states the snapshot/`GET /state` exposure; a needy-world
  wire test.
- **H5 spec vs plan on purity.** FR-003, Key Entities and the
  save/resume Edge Case say the schedule is a pure function re-derived
  on resume; research D1 says level release depends on the need path and
  the snapshot is authoritative. Fix: amend the spec (draws are pure;
  state persists).
- **H6 SC-002 clause 2 impossible.** The master stream deals one seed
  per kitty per tick and the turn order draws scale with the roster, so
  "add a needy seat, master stream untouched" cannot pass. Fix: restate
  as (i) equal right after generation and (ii) before the first onset a
  needy seat equals the same seat on `teacher` except `needy` and
  `behavior`; add a task.
- **H7 onset 0 and gap 1 dead states.** The `==` onset test can never
  fire for a first onset of 0 (the first advance publishes tick 1) and
  gap 1 stalls the schedule. About 2% of default worlds would never
  open. Fix: `>=` or `max(lo,1)` on the flat draw; gap.min ≥ 2 or chain
  transitions in one step.
